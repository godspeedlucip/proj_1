# 双基线 v2 工作流

本入口将配置、模拟/前处理、训练、完整推理和独立评价连接起来。旧的 `stent_repro.training` 仍是预生成样本替代训练入口；v2 使用 `python -m stent_repro.workflow`，要求更完整的物理元数据和来源记录。

当前已完成 CPU 小体模工程验证。原始患者投影、作者器械模型/能谱、正式测试集及完整尺寸 GPU 验证仍缺，不能将工程验收报告作为论文复现精度。

## 1. 运行环境和配置

在项目根目录的 PowerShell 中运行：

```powershell
$env:PYTHONPATH = 'src'
python -m stent_repro.workflow --help
python -m stent_repro.workflow validate --config configs/workflows/g0_a.yaml
```

依赖见 `pyproject.toml`，新增 scikit-image，用 `skeletonize(method='lee')` 做 3D 骨架化。当前已验证环境为 Python 3.14、PyTorch 2.11.0+cpu、scikit-image 0.26.0。

| 配置 | 用途 |
| --- | --- |
| `configs/workflows/g0_a.yaml`、`g0_b.yaml` | 小体模、缩小通道、明确标记 compact-g0；仅工程检查 |
| `configs/workflows/task_a.yaml`、`task_b.yaml` | 0/30/60° 课题配置模板，需要替换真实标定、网格和数据版本 |
| `configs/workflows/task_b_one_channel.yaml` | 课题 B 单通道独立训练配置 |
| `configs/workflows/reference_a.yaml`、`reference_b.yaml` | 各论文原始视角配置模板，并非已经完成原文复现 |

配置严格拒绝未知键、角度/通道冲突和不支持的旋转网格。A 原文训练 epoch/每轮样本数未给出，模板保持 null，启动前必须显式填写。不要把小体模配置改名为 task 后直接宣称正式实验。

体数据顺序为 `[z,y,x]`，spacing/origin 按 `[x,y,z]`，单位 mm；探测器尺寸为 `[height,width]`。所有模板几何均需检查实际视野，尤其不能只将 B 的 0.6 mm 改成 0.1 mm 而保持未经检查的体素数和训练数据。

## 2. 一键工程验收

```powershell
python -m stent_repro.workflow smoke --output outputs/g0_new_run
```

输出目录必须不存在或为空。命令生成互不泄漏的合成 train/validation/test，分别训练 A/B 两阶段的小网络，在同一个测试病例上从含背景投影完整推理，再由独立评价器读取真值。另保存绕过 DTE 的理想投影诊断。

产物为 `report.json`、每法的数据/模型 STL/参数、prepared 样本、训练检查点、DTE 和几何中间结果、概率体、二值体、逐例 CSV 和评价汇总。`software_chain_passed` 只表示流程没有执行失败。空预测、结构距离失败和低 Dice 仍按实际结果记录。

修复后重新生成的验收运行在 `outputs/g0_validation_final/`，其中 `ablation_matrix/` 还保存了一个种子的五个消融任务。其 compact 模型和两轮训练没有科学精度或泛化结论。旧的 `outputs/g0_validation/` 留作审计，不作为当前源码的验收记录。

## 3. 分步运行

### 3.1 数据生成与前处理

```powershell
python -m stent_repro.workflow simulate --config configs/workflows/g0_a.yaml --counts 3 1 1 --output outputs/demo_data
python -m stent_repro.workflow prepare --config configs/workflows/g0_a.yaml --manifest outputs/demo_data/raw.json --output outputs/demo_prepared
```

模拟器提供弯曲支架环/连接杆、导丝和线圈，输出 STL 及随机参数。体素真值用采样管状中心线的占据规则，网格为八边形管面；两者边界存在明确记录的近似。背景为解析合成，投影采用单色有效衰减。这不是作者的八种支架设计、患者数据或完整多色模拟。

使用自己的数据时，raw 清单沿用 `docs/投影与真值前处理.md` 的 cases 格式。v2 要求已校准的 line_integral 背景、明确角度，以及与配置一致的 truth grid；探测器原始强度须先按已知平暗场校准。含器械实测图须标 `measured_with_tool` 并确认配准，程序不再叠加器械。

正式运行还要求配置 `geometry.calibration_id`、投影元数据中的标定编号相同，且 `provenance.geometry_calibrated: true`、`dataset_version` 为实际冻结版本。编号应指向保留的标定记录。投影声明的 SDD、SID、像素大小、探测器尺寸和角度必须与配置一致；仅数组尺寸相同不足以通过检查。程序核对声明和编号，不能替代实际标定。

纯无器械背景会输出 `dte_pools.json`，存储整幅独立背景和器械投影源，支持训练时重新组合、裁块和放置。含实测/混合来源的数据使用配对 `dte.json`，会标为 paired surrogate，不能称为完整在线池训练。

### 3.2 资源预检

```powershell
python -m stent_repro.workflow preflight --config configs/workflows/g0_a.yaml --stage dte --device cpu --measure --output outputs/preflight_a.json
```

不加 `--measure` 只报告结构、解析几何检查和参数/优化器内存下界；加上后才执行真实配置的前向、反向和 Adam 步骤。CPU 不报告 GPU 峰值显存。B 的论文 DTE 很大，不能根据 meta 形状测试推断它能在现有硬件训练。

正式训练在分配网络之前要求 `--preflight-report <报告.json>`。报告必须来自 `preflight --measure --output <报告.json>`，并匹配阶段、有效网络配置、batch/patch、设备和运行环境，包含有限梯度及已分配的优化器状态。小网络或仅 meta 的报告不能用于原尺寸正式训练。A 的 C 消融和 B 的通道消融可以共用各自匹配的 DTE 报告；DTR 必须匹配实际输入通道与形状。

### 3.3 训练与恢复

```powershell
python -m stent_repro.workflow train --config configs/workflows/g0_a.yaml --manifest outputs/demo_prepared/dte_pools.json --stage dte --device cpu --output outputs/demo_a_dte
python -m stent_repro.workflow train --config configs/workflows/g0_a.yaml --manifest outputs/demo_prepared/dtr.json --stage dtr --device cpu --output outputs/demo_a_dtr
```

A-DTE 使用仅由训练数据更新的运行统计，验证/推理冻结；DTE pool 每次重新采样背景、器械、位置、光子计数、模糊和允许的散射。DTR 随机裁块；B 同步旋转/翻转输入与标签。每轮 `train_pairs`/`validation_pairs` 真正控制数量，有放回采样，尾批保留。

best 的 DTE 标准是固定验证面板 MAE 最低；DTR 标准是固定完整验证病例二值 Dice 宏平均最高。last 始终保存。训练 soft Dice loss 与二值 Dice 分开记录。

恢复时沿用相同输出目录并传 `--resume outputs/demo_a_dte/last.pt`，配置中的当前阶段 epochs 应增大。除该 epoch 上限外，网络、源文件哈希、采样配置和其他训练设置须一致。数据文件内容或旁车元数据变化会被拒绝。

旧 prepared 入口的检查点可按旧默认训练设置继续恢复，缺失的新增契约字段使用等价旧值，已有 best 不会因恢复而被劣化结果覆盖。旧检查点不能直接冒充具备 v2 几何及来源契约的推理检查点。

### 3.4 推理与评价

```powershell
python -m stent_repro.workflow infer --config configs/workflows/g0_a.yaml --manifest outputs/demo_data/inference.json --dte outputs/demo_a_dte/best.pt --dtr outputs/demo_a_dtr/best.pt --output outputs/demo_inference
```

推理清单只允许 `id`、`entity_id`、`projections`，禁止 truth。A 为 DTE→FDK→相邻切片 DTR；B 为 DTE→三个反投影通道→3D DTR。整幅 padding 会在返回前去除。可显式启用 inference.tiling，按 stride 对齐分块并输出覆盖图；整幅与分块可能因边界上下文不同而存在差异。输入超出明确体素限制仍会报错。

正式推理须先冻结输入清单、投影和旁车元数据的内容哈希，并将冻结文件传给 `infer --frozen-inputs`：

```powershell
python -m stent_repro.workflow freeze --manifest outputs/demo_data/inference.json --output outputs/frozen_inference_v1.json
# 正式 infer 命令补充：--frozen-inputs outputs/frozen_inference_v1.json
```

冻结文件不会覆盖既有版本。推理核验冻结内容，并在报告保存输入指纹与权重哈希；运行中的内容变化也会被拒绝。G0 允许本次运行自动生成指纹。损坏的 NumPy 文件记录为对应病例的流程失败，保留评价分母。

评价清单单独关联预测概率体和真值，例如：

```json
{"threshold":0.5,"cases":[
  {"id":"test_0000","entity_id":"stent01","probability":"demo_inference/case_00000/probability.npz","truth":"demo_data/test_0000_truth.npz"}
]}
```

文件路径相对于该评价清单。随后运行：

```powershell
python -m stent_repro.workflow evaluate --manifest outputs/demo_evaluation.json --output outputs/demo_evaluation
```

概率先按世界坐标重采样到真值网格，再阈值化；预测视野不能覆盖目标网格时记录失败，不能以零填充掩盖截断。报告 Dice、precision、recall、两个方向的骨架最近邻平均距离（mm），同时保留失败率和每个指标的有效病例数。空预测不输出伪造的零距离。

原文 A 的 MAPE 和 100 μm 膨胀/腐蚀容差指标尚未冒充实现；需进一步核实实测像素支持域及确切公式。当前投影评价函数提供 MAE 和前景/背景分区误差。

## 4. 消融与多种子矩阵

```powershell
python -m stent_repro.workflow matrix --config-a configs/workflows/task_a.yaml --config-b configs/workflows/task_b.yaml --seeds 17 42 73 --output outputs/task_matrix.json
```

该命令生成 15 个具名任务：每种子 A 的 C=1/3/5、B 的三/单通道。矩阵目前以 Python 接口 `run_matrix(matrix, manifests, output, execute=True)` 顺序执行；manifests 按 A/B 提供 `dte`、`dtr`、`inference`、`truth` 和可选 `device`。正式运行各方法另提供 `preflight`：`dte` 键指向共用 DTE 报告，运行名键下的 `dtr` 指向该任务 DTR 报告，例如 `{"dte":"A_dte.json","A_C1_seed17":{"dtr":"A_C1_dtr.json"}}`。先核对真实数据再启动执行，矩阵在训练前冻结测试输入与真值，并逐任务复核。

同种子、同方法的 DTR 消融复用符合条件的 DTE；复用键由 DTE 配置、几何、种子、采样设置和源文件指纹计算，任务名称不会覆盖这些条件。不同种子独立训练。矩阵检查两法使用共同的测试输入、真值和病例身份，训练错误逐任务保留。主报告仍需在实体级汇总多位置/多噪声采集，不能将每张切片当成独立病例。

## 5. 最新运行验收

已补齐实体统计、多色谱、空间相关错误、AMP 与激活重计算、重叠分块、几何分辨率检查、跨框架探针和 A 随机起始角/17 视图。原始训练 batch/patch 已在 RTX 4070 Ti SUPER 上实测；B 使用明确记录的混合精度和重计算。

用户提供的 nerve 合成数据已有连续工具投影与独立三维真值，已新增 `import-nerve` 适配器。完整来源、原生数据短程矩阵、测试结果和复跑命令见 [补齐与运行验收](补齐与运行验收.md)。本轮按用户“确认可以正常跑就行”的要求验收，没有启动多周训练，也没有将短程结果标为论文精度复现。

同一 CLI 新增 `run-matrix`、`summarize-matrix`、`benchmark`、`geometry-check`、`framework-probe`、`evaluate-dte` 和 `calibrate-errors`；各参数通过 `--help` 查看。参考视角清单使用 `matrix --reference`，不同采集几何须分别准备训练，不能作为同几何的课题矩阵直接混跑。

历史 G0 证据仍见 [实施验收记录](实施验收记录.md)。最新要求与状态见 [Spec](superpowers/specs/2026-11-16-dual-baseline-fidelity-design.md)、[补齐 Plan](superpowers/plans/2026-11-16-completion-plan.md) 和 [执行记录](superpowers/plans/2026-11-16-completion-progress.md)。
